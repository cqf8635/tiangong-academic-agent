## 18. 按用户核心设计判定硬编码去留

硬编码候选数不构成修改授权或修改清单。判断依据是《科研智能体核心设计记录.md》：本轮原话与当前任务优先；主体与任务分别维护；本地优先、在线按需；已有内容通过共享池按需复用；主研负责最终稿，专家与审核者给出可定位意见；资源预算不能静默改写需求或丢掉内容。

### 18.1 与设计直接冲突：应从任务语义决策中移除

| 当前规则 | 与设计的冲突 | 应保留的能力 |
| --- | --- | --- |
| 解析失败按 **6 字符**及问号分流；固定意图先决定目标 agent | 用长度/标点或固定单标签代替当前轮原话，不能承载多动作、条件及排除要求 | 可保留支持能力的注册表，但选择处理能力应结合主体、任务、上下文语义 |
| 无条件补本地资料源；有检索词就触发在线搜索；其他字段覆盖“不联网” | 检索方式应在理解本轮任务后决定；本地优先、在线按需 | 用户显式要求的新资料与时间范围应优先执行；纯理论题可不检索 |
| 固定只有 **1 路**在线瓶颈、只取前 **3** 个专家子任务等规则直接限定语义覆盖 | 预算上限被当成“任务只有这些子问题”的结论 | 并发/任务上限可作为预算；需分批或标明未完成部分，不能静默丢掉关键动作 |
| 只要候选池非空就沿用；默认第一条候选；把用户讨论文本赋成 **0.98** 文献证据 | 复用没有绑定当前任务、选定对象、来源和版本；用户提供文本不等于已获取论文证据 | 保留共享资源复用，但先核对任务身份；显式选篇优先；分开标注用户材料、元数据、摘要、全文 |
| 主题匹配失败仍回灌旧主题；清空消息但保留上下文状态 | 连续性变成机械继承，与主体和任务分别更新、会话状态可控的要求冲突 | 保留有效历史成果；换任务/换主体/清空时按设计更新适用状态 |
| 用 **200 字符**门槛跳过审核，并固定写入“已审查/已重构”类结论 | 审核是否运行应按任务和收益决定，状态说明必须反映实际操作 | 可按需跳过审核，但应如实记录未审核；由主研综合意见并负责最终稿 |
| 长文只把前 **2,600 字符**送入修订、EPUB 每章只取 **3,000 字符**却当完整内容 | 直接违背按语义切片完整传输和不静默丢内容要求 | 单次调用仍可设 token/块预算；按结构续传并标记尚未覆盖范围 |
| 固定来源分值/权威标签被用作相关性或同行评议证明 | 来源身份、内容类型与任务相关性不同；归档来源不能替代证据核验 | 保留来源分类和来源元数据，相关性与证据等级需按真实资料判断 |
| 启动后台全学科雷达同步，不以用户进入页面或明确检索为条件 | 资料机制应围绕当前任务与需求触发，不能由无关启动流程产生无需求网络请求 | 保留缓存及明确刷新能力，刷新范围应绑定页面筛选或当前任务 |
| 固定领域物理边界提示用于跨领域回答 | 与跨学科定位和条件化推理冲突，模板可能强加无关前提 | 保留可复用写作结构；边界内容由当前学科与题目条件生成 |

### 18.2 需要条件化：数字可以保留，使用方式要服从设计

- **最近三年**：这是用户对适用的近期研究任务给出的默认时间窗，不是所有检索的全局过滤器；明确的用户时间条件优先，任务不涉及近期研究时不强加。
- **24 小时**：这是用户提出的复用后可重新检索的设计线索，不是已定案 TTL。还需明确按哪一轮/哪次抓取计时、刷新哪些来源、失败时如何使用旧资料。不得自行把它实现成所有资源统一过期时间。
- **RAG 阈值、相似度和去重阈值**：可以作为按检索器/模型校准的技术门槛；不得跨不同分数体系直接比较，或将阈值包装成“证据可靠度”。资料不足时应呈现不确定性。
- **top-k、块长、并发、超时、重试、上传体积等预算**：可继续作为成本和资源控制。超过预算时需分批、停止并说明缺口或返回可恢复状态，不能把截断内容伪装成完整答案/全文。
- **缓存版本与失效规则**：固定版本号是正常实现手段；缓存身份仍须关联内容版本/哈希及适用生成配置，缓存命中不能只凭标题或文件名。
- **学科/来源/agent 注册表**：作为可验证的能力目录可以保留并扩展；不能将它变成封闭的任务意图清单或固定角色席位。跨学科角色数量和检索来源随本轮需求调整。
- **审核默认开关**：可以作为部署配置；实际是否审核还要考虑任务风险、用户要求和当前稿件问题。关闭时不得宣称已审核；开启也不能让每个专家重写整份终稿。

### 18.3 与任务语义无关或设计已要求的硬编码：暂不列为整改项

- `INIT/INHERIT/APPEND/REPLACE` 等状态协议、API 字段/HTTP 路由、sender/source/status 枚举，只要对开放主体和任务提供支撑，不因其是固定字符串就要删除。
- 前端颜色、间距、图表/公式语法适配、导出画布布局、系统默认模型路径等属于产品展示或实现默认值；应检查配置能力和跨环境可用性，不能与语义路由硬编码混为一类。
- 语音中的设备、阈值、停止词和模型加载实现本轮仅记录现状。核心设计记录说明语音此前要求不要修改，新项目迁移范围仍待确认；未经后续明确要求，不将这些候选作为本轮修改对象。
- 安全上限和正确性校验可保留；但它们应防止资源耗尽和数据损坏，不应误判用户意图或把失败说成成功。

因此硬编码处理原则不是“把 409 个位置改掉”，而是优先移除上表 18.1 中**改变任务语义、造成静默遗漏、混淆资料身份或伪报执行结果**的规则；18.2 由任务/资源/校准条件驱动；18.3 暂不改。此处为设计对照结论，不代表已实施任何整改，也不覆盖用户尚未确认的共享池持久化、24 小时刷新协议和语音迁移方案。
