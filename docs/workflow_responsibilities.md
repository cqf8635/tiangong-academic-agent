# 工作流与模型职责

规则能否移出提示词，取决于程序是否拥有足够信息核验它。流程状态、编号、输入输出类型和原文完整性由代码保证；任务含义、相关性和理论是否成立仍需模型判断。程序不以关键词、篇幅或条数替代语义判断。

| 环节 | 工作流负责 | 模型负责 |
| --- | --- | --- |
| 输入 | 原始文字独立保存，图片转录单独记录 | 转录图片、结合语境理解原话 |
| 任务确认 | 在现有规划调用内对照原话；校验修正字段；保存初始解释、修正差异和理由 | 判断主体、动作、条件、预期成果是否理解正确 |
| 任务传递 | 本轮 task_snapshot 为统一状态；各节点获取独立副本；补查作为从属任务 | 对统一任务进行专业分析，不自行增加验收条件 |
| 时间 | 计算默认最近三年，并在任务修正后再次规范化；明确时间和不限时间优先 | 识别用户明确时间、相对事件锚点和不限时间要求 |
| 资料渠道 | 校验共享项真实存在，去掉虚构或重复 ID；执行已选渠道 | 判断专业任务是否需要证据、已有资料是否适用、还需要哪些来源 |
| 检索 | 保留既有查询去重、进展判断、预算和实际执行记录 | 提出具体缺口及有价值的新策略；判断语义重复 |
| 证据传递 | 本地、在线、审核统一资料格式和全局编号；保留已读取内容 | 依据元数据、摘要、切片、全文等实际查看范围解释主张 |
| 写作 | 本地与在线共用精简作者规则；传递统一任务和证据 | 完整组织已有成果、解释、条件及后续方案，区分事实、推导和建议 |
| 审核 | 校验缺陷所引原句存在、来源编号有效；规范类型；重写标志不控制正文 | 判断任务匹配、理论与事实依据、实质遗漏；给可定位理由与不确定性 |
| 补查追加 | 去重后只传新增资料；程序拼接补充，保留原正文；无新增则不生成补充 | 从新增资料中提取有用信息、解释矛盾，避免复述 |
| 交付 | 记录未知、已排除或无可读内容的数字引用；保存任务与检查记录；下一轮清空临时状态 | 判断数字括号是否确实是引用、引用是否支持所在主张 |

数字引用检查只生成诊断，不自动删文、补查、拒绝答案或触发新模型调用。原句存在只说明可定位，不证明审核意见正确。任务修正理由标记为模型判断；默认时间的规范化另标为系统策略。

简化的是重复的流程指令，不是回答内容，也不限制回答长度。研究进展和未来方案均保留；跨领域任务不强制套用公式、代码或实验模板。原有补查仍可运行，补查结果追加到正文。

本次不增加模型调用或审核轮次。自动化测试使用本地桩，不据此声称真实模型的语义误差已经消失。

## 节点数据通行与失败处理

各节点保留可用数据并继续原有流程。审核缺项、资料日期未知、专家失败、模型输出截断均如实记录，不据此自动重写、裁文或增加检索调用；补查继续只由具体的信息缺口和现有规划驱动。

- 初查、跨轮补查使用共同的来源合并规则：等价 DOI/arXiv/URL 尽量合并，本地不同页和仓库不同版本保留；相同来源的新正文与摘要合并保留，全局编号不变，追加只消费内容差量。
- 共享资料选中后会加载实际来源；历史生成正文仍只作为上下文。短的新片段也会保存，不再只取较长文本。
- 跨模态作者和审核接收同一资料池；文档与跨模态兜底复用原计划、活动文档、学科、排除词及时间边界，已执行的初查不再由作者重复扫描。
- 已知越界日期仍过滤；缺少日期的本地资料保留并标记日期待核实，不视为已经证实满足时间条件。
- 会议按指定/会话已选择记录优先处理，未指定才沿用最新记录；指定文件失效不会悄悄改读另一场会议。聊天保留完整报告字段，审核接收实际记录。
- 专家在资料准备后执行全部已识别子任务，保持最多两路并发；失败记录不再生成成功结论，主作者继续承接。专家输出不是独立证据。
- 最终审核对照原任务项记录检查状态；存在严重问题或漏记检查时不能标记通过，但正文继续交付，不自动把“未检查”解释为“漏答”或新检索任务。
- 图片转录有独立依据通道；资源聚焦后的主体、活动文档和任务快照同步。控制类操作区分具体动作，未执行不会报告“已执行”。
- 模型响应保留终止原因；截断文本照常传递并记录未完整结束，PDF 页转录未正常完成时不写成完整缓存。追加完成状态与原回答的完成状态分开保存。
- 流式回调按请求隔离，内部审核、归纳与专家输出不作为用户正文广播。归纳是否调用模型只由配置决定，测试替身不改变生产分支。

## 剩余缺口的处理

- 资料排除沿用原有覆盖评估和审核调用，需能定位到需求（或图片转录）及目标资料两侧的原句；标题也可用于定位。缺少依据、编号错误或结构异常时保留资料，记录 `relevance_review.basis_status=unverified`，不阻断交付或自动补查。定位成功仍是模型给出的相关性判断，不证明排除在语义上必然正确。
- 聊天控制通过请求隔离的执行器接入已有录音管理、会话音色设置和会话清空。控制参数随统一任务传递，实际结果通过 `control_result` 返回及保存；未接执行器的独立入口明确记录未执行。录音启动、正在停止和执行失败分别报告，界面沿用真实返回状态。清空在工作流停止写检查点后执行，不再把旧话题、答案或证据发布回已清空会话。
- 默认朗读不再截取前 10000 字；MCP 也不再仅朗读前 150 字，统一复用全文合成入口。音频成功后才原子写入缓存；MCP 请求 WAV 时执行真实格式转换。已有代码块、公式等口语化清洗仍保留，不据此改动文字正文。
- 离线回归覆盖多个学科的原话、全部任务项、资料末尾、回答末尾在作者与审核之间的传递，以及生产默认归纳分支。它检验流程是否漏传或裁减，不代表已完成真实模型的新旧回答质量对照。未追加自动模型评判、重写或收费评测调用。

这些是流程和数据完整性约束，不证明模型解释、相关性或理论判断必然正确。语义判断保留在原有智能体中，不增加通用重写节点。

## 审核到补查的触发边界

审核意见保留，但不再凭一个非空查询自动补查。`evidence_requests` 通过 `finding_ids` 关联本次具体缺陷；`purpose=missing_task` 需关联缺项检查和可定位的需求依据，已有任务清单时还需关联有效任务编号。检查结果已经为 `met` 的完整性建议作为 `advisory` 留存，不再触发补查。`purpose=verify_claim` 则需定位回答中的实际主张，任务已完成也能核实具体事实；不要求先找到反证才能补证。

缺少关联、可选深化或无法定位的请求保存在 `deferred_evidence_requests`，不触发新增模型调用，也不裁改正文。广泛研究介绍不自动要求全领域均衡、全文、全部实验指标或误差条。该语义边界由原有审核调用判断，代码核对任务关联和审核前后一致性，不能证明模型判断永远准确。

补查规划沿用既有调用选择资料渠道和共享来源；实际查询由该条审核缺口确定，可附英文表达。原任务仅提供语境和限制，不再进入补查任务的综述意图或子查询。规划器提出的额外查询记录在 `proposed_queries`，不会作为一轮新综述执行。多个独立缺口仍分别处理，检索失败不丢弃其他缺口的结果，新资料继续去重并追加。
